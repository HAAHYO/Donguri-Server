# 커밋 컨벤션

## 형식

```
<type>: <한국어 요약>

<선택: 본문 — 왜 바꿨는지>

Co-Authored-By: ...
```

| type | 용도 |
|------|------|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `test` | 테스트만 추가/수정 |
| `docs` | 문서 |
| `chore` | 자잘한 작업, 하네스, 설정 |
| `build` | Gradle, 의존성 |
| `ci` / `cd` | 워크플로 |
| `perf`, `style`, `init` | 성능 / 포맷만 / 초기화 |

제목은 72자 이하(hook이 검사), 명사형으로 끝낸다(`추가`, `수정`, `삭제`, `변경`).

| 나쁨 | 좋음 |
|------|------|
| `feat: 기능 추가` | `feat: 도토리 생성 API 추가` |
| `fix: 버그 수정` | `fix: 존재하지 않는 도토리 조회 시 404 반환` |
| `feat: API 추가 및 예외 처리 및 테스트` | 커밋 3개 |

## 커밋 경계

"이 커밋이 무엇을 했나?"에 **"그리고/및"** 이 필요하면 나눈다. 단위는 **하나의 관심사**다 — 대개 파일 하나지만, 5개 파일에 걸친 이름 변경 하나는 커밋 하나다.

- 기능 코드와 그 테스트는 **같은 커밋**에 둔다 (각 커밋에서 `./gradlew check` 가 통과해야 하므로).
- 버그 수정 + 그 김에 한 포맷 정리 → 두 커밋.
- 의존성 순서: 설정/빌드 → 도메인/엔티티 → 예외 → 서비스 → DTO → 컨트롤러 → 문서. 모든 커밋이 컴파일되어야 한다.

## 절차

1. `git status --short`, `git diff` 로 실제 변경을 확인한다. 이번 작업과 무관한 변경이 있으면 커밋하지 않고 사용자에게 알린다.
2. 경로를 지정해 스테이징한다 — `git add <path>` (`-A`, `.` 은 hook이 차단).
3. `git diff --staged --stat` 으로 메시지와 내용이 맞는지 확인한다.
4. 한국어가 깨지지 않도록 heredoc으로 커밋한다:
   ```bash
   git commit -m "$(cat <<'EOF'
   feat: 도토리 생성 API 추가

   Co-Authored-By: ...
   EOF
   )"
   ```

## 규칙 (hook 강제 항목 포함)
- main 에서 커밋하지 않는다 — 브랜치 `<type>/<kebab-주제>` (hook 강제)
- `--no-verify` 금지 (hook 강제), force push 금지 (권한 deny)
- push된 커밋을 amend 하지 않는다. 새 커밋을 쌓는다
- 비밀값을 커밋하지 않는다 — 새 설정 파일은 스테이징 전에 읽어본다
